# 个人微信真实联系人接入设计

日期：2026-08-28  
执行者：Codex

## 目标

将“接收人/群聊列表”替换为个人微信账号实际可见的联系人和群聊，并允许为每个真实对象配置智能体、工作区和自动回复模式。

## 范围

- 使用 Wechaty SDK 和受支持的 Puppet 服务连接个人微信。
- 登录后同步联系人、群聊和头像，并将结果写入现有联系人存储。
- 接收真实入站消息、更新会话记录，并依据已有规则触发智能体回复。
- 通过真实会话发送自动回复和手动测试消息。
- 删除个人微信模式中生成固定账号、伪造登录成功和仅记录发送日志的实现。

不包括企业微信通讯录，也不实现或维护自定义微信协议。

## 配置契约

个人微信模式新增以下配置：

```toml
[channels.wechat.personal]
puppet = "service"
puppet_service_token_env = "WECHATY_PUPPET_SERVICE_TOKEN"
puppet_service_endpoint = ""
```

`WECHATY_PUPPET_SERVICE_TOKEN` 由 Puppet 服务供应商提供。没有此凭据时，启动必须明确失败并说明无法读取真实联系人，而不能显示虚拟联系人。

## 架构

新增 `WechatyPersonalDriver`，实现既有 `WeChatPersonalDriver` 接口，并补充联系人同步能力：

```text
Wechaty Puppet
  -> WechatyPersonalDriver
  -> WeChatChannel
  -> WeChatContactStore
  -> GUI 联系人/群聊列表与自动回复规则
```

驱动在登录完成后遍历 `Contact.findAll()` 与 `Room.findAll()`，保存稳定 id、显示名称、类型和头像。消息事件以真实 contact/room id 写入现有会话存储；发送操作根据 id 找到真实 Contact 或 Room 后调用 SDK 发送。

## 数据与规则

- `ChannelContact.id` 使用 Puppet 返回的稳定对象 id，禁止使用时间戳生成联系人 id。
- 同步仅更新身份信息和最近活动字段，保留用户配置的 `agentId`、`workspace`、`autoReply` 和 `replyMode`。
- 联系人或群聊未在本次同步中出现时不自动删除，避免临时权限或同步异常导致规则丢失；GUI 标记为“本次未发现”。
- 手动添加个人微信虚拟联系人入口移除。联系人列表为空时只提供“登录并同步”操作和失败原因。

## 运行与诊断

GUI 显示登录状态、当前账号、最近同步时间、联系人数量、群聊数量及最近同步错误。提供“立即同步”按钮，触发驱动刷新而不重新创建会话。

失败结果需要区分：缺失 Puppet 凭据、登录失败、同步失败、联系人不存在、发送失败。原始供应商错误保留在诊断日志中。

## 验证

- 单元测试：配置缺失、真实联系人映射、群聊映射、同步不覆盖自动回复规则、发送目标解析。
- 通道测试：真实驱动事件进入现有自动回复和会话存储链路。
- 适配器测试：使用 Wechaty API 桩验证登录、联系人同步、消息接收和发送调用。
- 手工验收：使用供应商测试账号完成扫码登录，确认好友/群聊显示、规则保存以及一条私聊和一条群聊回复。

## 风险与约束

个人微信没有稳定的官方联系人 API。Puppet 服务的可用性和账号风控由供应商及微信策略决定；项目只依赖其公开 SDK 契约，不实现逆向协议或伪造联系人数据。
