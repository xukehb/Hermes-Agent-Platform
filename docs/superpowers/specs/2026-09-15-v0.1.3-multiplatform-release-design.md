# Hermes Agent Platform v0.1.3 多平台发布设计

日期：2026-09-15
执行者：Codex

## 目标

将 Electron 桌面应用统一命名为 `Hermes Agent Platform`，版本更新为 `0.1.3`，并通过 GitHub Actions 在 Windows、Ubuntu 和 macOS 原生运行器上构建安装包，最终发布到 GitHub Release `v0.1.3`。

## 发布产物

- Windows：NSIS 安装版 `.exe` 与 Portable `.exe`。
- Ubuntu：Debian 安装包 `.deb`，目标架构为 x64。
- macOS：磁盘镜像 `.dmg`，分别构建 x64 与 arm64。
- GitHub Release：标题使用 `Hermes Agent Platform v0.1.3`，集中挂载上述产物。

所有安装包的产品名、文件名和可见应用名均使用 `Hermes Agent Platform`，不得出现 `ChatGPTConnect` 或 `CodexConnect`。

## 架构

在 `package.json` 中维护唯一的版本和 electron-builder 产品配置。新增按平台划分的 npm 打包命令，并由一个 GitHub Actions matrix workflow 在各原生系统运行器上执行。每个平台先安装锁定依赖、编译 TypeScript、重建 `better-sqlite3` Electron 原生模块，再调用 electron-builder 生成对应安装包。

各构建任务先上传临时 artifact；全部成功后由单一发布任务下载产物并创建 `v0.1.3` Release。工作流仅接受 `v*` 标签触发，并校验标签版本与 `package.json` 一致，避免错版发布。

## 文件职责

- `package.json`：保存 `0.1.3` 版本、产品名、平台目标与本地打包命令。
- `package-lock.json`：锁定版本元数据及新增的 `electron-builder` 开发依赖。
- `.github/workflows/release.yml`：测试、三平台原生构建、产物汇总和 GitHub Release 发布。
- `tests/package-scripts.test.ts`：验证产品名、版本、平台目标及发布工作流契约。
- `README.md`：记录新的本地打包命令、产物和未签名包限制。

## 错误处理

任何测试、类型检查、原生模块重建或平台打包失败都会阻止发布任务运行。Release 使用 GitHub 自动提供的 `GITHUB_TOKEN` 和最小的 `contents: write` 权限，不引入额外发布密钥。由于当前没有 Windows 和 Apple 签名证书，v0.1.3 明确发布未签名包；系统可能显示未知发布者或 Gatekeeper 提示。

## 验证

本地执行配置契约测试、完整 Vitest、类型检查、编译和 Ubuntu `.deb` 构建。GitHub Actions 分别验证 Windows、Ubuntu、macOS 的真实构建结果，并仅在所有平台完成后创建 Release。发布完成后检查 Release 标签、标题，以及 `.exe`、`.deb`、x64 `.dmg`、arm64 `.dmg` 文件是否齐全。

## 范围边界

本次不购买或配置代码签名证书，不改变应用业务功能，也不清理当前工作区中用户尚未提交的 GUI 修改。发布提交会包含这些用户修改，确保 GitHub runner 构建的是当前期望的软件状态。
